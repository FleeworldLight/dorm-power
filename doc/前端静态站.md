# 前端静态站（`dist/`）

纯 HTML / CSS / JS，没有构建步骤，没有依赖。**这个目录整体丢进 GitHub Pages 就能用。**

后端在 `web/`，只提供 JSON 接口，两边通过 CORS 通信。

## 先改这一行

`config.js`：

```js
window.API_BASE = '';
```

| 场景 | 填什么 | 为什么 |
|---|---|---|
| 后端同域部署 | `''`（留空） | 走相对路径，同源请求，不需要 CORS |
| GitHub Pages | `'https://xxx.app.workbuddy.host'` | 跨域，**必须**在后端登记本站域名 |
| 本地调试 | `'http://localhost:3000'` | 同上，后端要放行 `http://localhost:8080` |

填了域名之后，去后端的 `web/config.json` 把前端来源加进白名单：

```json
{
  "cors_origins": ["https://你的用户名.github.io"]
}
```

**漏了这一步的典型症状**：页面能打开，但一直显示「还没有添加宿舍」，
点扫码报「连不上后端」。真实原因是浏览器把响应拦了，
JS 看不到细节（CORS 失败对 JS 是黑盒），所以前端只能给个笼统提示。
按 F12 看 Console 会看到 CORS 字样——那才是实话。

## 部署到 GitHub Pages

仓库里有两个目录，别搞混：

| 目录 | 角色 |
|---|---|
| `dist/` | **源文件**，唯一真相。改前端改这里 |
| `docs/` | **发布产物**，由 `sync-docs.sh` 从 `dist/` 复制生成。别手改 |

改完前端跑一下：

```bash
bash sync-docs.sh      # dist/ -> docs/
git add dist docs
git commit -m "update frontend"
git push
```

然后在 GitHub 仓库里：

1. **Settings → Pages**
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，目录选 **`/docs`**

> **为什么必须选 `/docs` 而不是 `/(root)`**：
>
> 两个硬理由：
>
> 1. **根目录没有 `index.html`。** Pages 找首页只认发布目录下的
>    `index.html`，而它在 `docs/` 里。选根目录会得到一个 404 或者
>    仓库文件列表页 —— **不是"不推荐"，是根本跑不起来**。
> 2. **会把整个仓库当站点发布。** 根目录直属文件合计约 219 KB，
>    其中 `monitor.py` 一个就 76 KB，还有 `doc/`、`web/` 整个后端目录。
>    这些都会变成可下载的网页。`data/cookies.json` 已被 `.gitignore` 排除所以
>    不会泄到线上，但把源码白送出去没有任何好处。
>
> `docs/` 里只有前端那 5 个文件（含 `.nojekyll`），发布它是安全的。

`docs/.nojekyll` 是个空文件，作用是让 GitHub Pages 跳过 Jekyll 处理
（Jekyll 会忽略下划线开头的文件，也可能改动产物）。别删。

### 放子目录也能跑

所有资源引用都是相对路径（`href="app.css"` 而不是 `href="/app.css"`），
所以 `https://user.github.io/repo-name/` 这种带路径的地址同样正常。

## 本地预览

```bash
cd dist
python3 -m http.server 8080
```

打开 `http://localhost:8080`。若后端在 `localhost:3000`，
记得把 `config.js` 改过去并且后端放行 `http://localhost:8080`。

直接双击 `index.html` 用 `file://` 打开**不推荐** ——
`file://` 下 `Origin` 是 `null`，会被 CORS 拦掉，而且 localStorage 行为也不一致。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 骨架。**没有模板占位符**了，标题由 JS 从接口配置写入 |
| `config.js` | 唯一的部署开关（后端地址、兜底标题） |
| `app.css` | 样式 |
| `app.js` | 全部交互逻辑：看板渲染、曲线绘制、扫码状态机 |

## 接口

前端只用到这些（`API_BASE` 会自动拼在前面）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/summary?utoken=` | 看板数据，**只返回自己那一间** |
| GET | `/api/me?utoken=&prefill=1` | 我的宿舍（带 `prefill=1` 才返回姓名学号） |
| DELETE | `/api/me?utoken=` | 删除我的全部数据 |
| POST | `/api/refresh` | 刷新自己那一间（打开页面自动调一次） |
| POST | `/api/session/start` | 开始扫码，返回二维码 |
| GET | `/api/session/state?sid=` | 轮询登录状态 |
| POST | `/api/session/levels` | 四级联动的选项 |
| POST | `/api/session/commit` | 选好房间 → 落库，返回 `utoken` |

`utoken` 存在 `localStorage.dorm_utoken`，是**唯一身份凭据**：
丢了就等于没绑定，重新扫码即可，同一间宿舍的历史会自动接上。

## 改了这个目录要记得

后端那边有两处和前端耦合，改前端时容易忘：

1. **`web/dorm/api.py` 的 `ALLOW_HEADERS`** —— 只有 `Content-Type`。
   前端要是加了自定义请求头，预检会失败，得同步补上。
2. **`web/dorm/api.py` 的 `ALLOW_METHODS`** —— 目前 `GET, POST, DELETE, OPTIONS`。
   新增动词要同步。
