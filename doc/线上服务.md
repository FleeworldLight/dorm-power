# 在线服务（`web/`）

部署成公网链接的宿舍电费查询平台。零第三方依赖，只用 Python 标准库，
加上系统自带的 chromium。

**各看各的**：没绑定的人进来什么都看不到；扫码绑定之后也只看到自己那一间。
服务端在数据层按 `utoken` 过滤，不是靠前端藏。

## 它怎么工作

1. 用户扫码：服务端开一个无头 chromium 打开学校入口，把支付宝登录二维码截图给用户；
   用户手机扫码后服务端接管会话，之后**纯 HTTP 重放**完成选房间和查余额，
   不需要再开浏览器。
2. 绑定后这间宿舍归该 `utoken` 所有，页面每次打开自动刷新一次，
   并按天记一个历史点。会话凭据加密落盘，默认 30 天不用自动删除。

也兼容本机脚本上报：`monitor.py` 用 `POST /api/report` 推数据
（`source: report` 的记录没有 `sealed`，线上刷不了，只能靠本机脚本自己刷）。

## 鉴权的实际情况（重要）

该站的三个接口鉴权并不一致，实测结论：

| 接口 | 是否校验登录 |
|---|---|
| `POST /index/getReserveAM`（查余额） | **完全不校验** —— 用编造的 `PHPSESSID` 也能返回真实余额 |
| `POST /index/getLevels`（房间树） | 同样不校验 |
| `POST /index/pay` | **真正校验** —— 有效会话返回 200 且注入 `var infoDataJson`，失效则 302 回支付宝 |

所以「会话过期」并不妨碍查到余额。本服务的处理是：

- **刷新不再被登录态卡住**。会话过期照样刷得出新值 —— 因为拦着也拦不住，
  只会让看板停在旧数据上（这正是它一开始的表现）。
- **范围仍然受限于已登记的宿舍**：只能刷新库里已经存在的记录，
  没有任何「按编号查任意房间」的入口（那个接口已经删掉）。
- `school.session_is_real()`（走 `/index/pay`）被保留下来，但只用来把
  「这次读数是不是来自验证过的登录」记进记录的 `verified` 字段，不再用来卡刷新。

## 历史怎么记（一天一个点）

曲线上的历史点是**按天**记的，不是每次刷新都往里塞：

- 每次刷新只更新记录里的「当前值」`remain` / `ts` 和当天的临时值 `pend`。
- 跨天时（`pend.day != 今天`），把上一天**最后一次**读数落档进 `history`。
  于是 `history` 天然是「一天一个点」。
- 曲线 = `history` + 当天那笔 `pend`，所以今天那个点会随刷新移动，历史不会越长越乱。
- 同一个宿舍如果因为换浏览器重扫而存在多条记录，`/api/summary` 会把**同一间**的
  历史并起来、按天去重后展示，不会出现「重扫后历史被清空」。
- 本机脚本 `POST /api/report` 走的是同一套按天规则。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 看板页（渲染 `templates/index.html`） |
| GET | `/static/<file>` | 样式与脚本，带 ETag，重复访问返回 304 |
| GET | `/healthz` | 存活探针 |
| GET | `/api/summary?utoken=` | **只返回调用者自己那一间**（看板数据源） |
| GET | `/api/diag[?qr=1]` | 环境探测：chromium、出网、二维码截图 |
| POST | `/api/session/start` | 开一个扫码登录会话，返回二维码 |
| GET | `/api/session/state?sid=` | 轮询登录状态 / 取新二维码 |
| POST | `/api/session/levels` | 代理四级联动的取选项 |
| POST | `/api/session/commit` | 选好宿舍 → 首次查询 → 落库 |
| POST | `/api/refresh` | 刷新自己那一间（打开页面自动调一次；同一宿舍 20 秒节流） |
| GET | `/api/me?utoken=` | 我的宿舍。加 `&prefill=1` 才返回姓名学号 |
| DELETE | `/api/me?utoken=` | 删除我的全部数据 |
| POST | `/api/report` | 本地脚本上报入口 |
| GET | `/api/export?token=` | 导出全部（需管理员口令） |
| POST | `/api/import?token=` | 导入（需管理员口令） |
| POST | `/api/admin/drop?token=&utoken=` | 删掉指定记录（需管理员口令） |

`utoken` 就是这个平台的唯一身份：`/api/summary`、`/api/refresh`、`/api/me` 全都按它来，
拿不出来就什么都看不到。`/api/me` 再加 `&prefill=1` 才会返回回填用的姓名学号。

## 数据与安全

**存在哪。** `data/` 目录下：`users.json`（看板数据）、`key.bin`（密钥）、
`profiles/`（扫码时用的临时浏览器 profile，用完即删）。
`users.json` 里不含明文姓名学号 —— 它们只存在于加密后的 `sealed` 字段中。

**怎么加密的。** 标准库没有 AES，所以用 `hashlib.blake2b(key=...)` 生成密钥流做异或，
再用 `hmac` 做先加密后 MAC（`store.enc_bytes` / `dec_bytes`）。
这是自建构造，**密钥与密文同机存放**，能防的是「拿到数据文件但拿不到 key.bin」，
不防拿到整台机器的人。清楚这一点再用。

**谁能看到什么。** 这是个**各看各的**平台，不是公开看板：

- 未绑定（或 `utoken` 对不上）的访客，`/api/summary` 返回 `bound: false` + 空列表，
  **一个字节别人的数据都不给**。
- 扫码绑定之后，也只能看到**自己那一间**的宿舍名、楼层、余额、更新时间、历史曲线。
- 服务端在 `summary()` 里用 `utoken` 定位记录，再按该记录的 `room_id` 取曲线，
  别的宿舍在数据层就被过滤掉了，不是靠前端藏。
- 姓名学号只存在加密块里，只有拿得出该 `utoken` 的 `/api/me?prefill=1` 才返回。

**会话怎么回收。** 闲置 15 分钟或状态异常的登录会话会被 `janitor` 线程回收
（关浏览器、删 profile）。数据里的凭据按 `session_ttl_days`（默认 30 天）过期。

## 部署

`web/` 目录整体打包上传即可，服务监听 `PORT` 环境变量、绑定 `0.0.0.0`。
`data/` 会留在远端沙箱里，重新部署不会清空。

`web/config.json`：

```json
{
  "admin_token": "……",
  "max_login_sessions": 4,
  "login_rate_limit": 20,
  "session_ttl_days": 30
}
```

`admin_token` 是导出 / 导入 / 删除记录的凭据，泄漏了等于把全部数据放出去，
别提交到公开仓库。

## 前端

`templates/index.html` 是骨架，`static/app.css` 与 `static/app.js` 是样式和交互。
页面加载后带着 localStorage 里的 `utoken` 拉一次 `/api/summary`：
没绑定就只显示「扫码添加宿舍」的引导，不渲染任何数据；绑定后只渲染自己那一间。
**然后自动触发一次刷新**（没有刷新按钮）：先把缓存数据画出来，
刷新到新数据再重画，所以打开就刷新但不会被它卡住。
服务端按宿舍做了 20 秒节流，反复刷新不会把学校站点打爆。
换了设备或清了浏览器数据就相当于没绑定，重新扫码即可 —— 同一间宿舍的历史会自动接上。

每张宿舍卡片里直接画出余额曲线，不用点开：横轴按天（窗口至少 5 天，今天永远在最右端），
纵轴整数刻度，数据点少时不会被拉成夸张的斜坡。**点曲线上的任意位置**，
会取横坐标最近的数据点，把它的数值和时间显示出来（再点一次收起）。

## 已知边界

- 同时登录的人太多会被限流（`max_login_sessions`）。
- 自动刷新对**没有服务端凭据**的记录无能为力 —— 本地脚本上报的 `source: report`
  记录线上不存 cookie，只能靠本地脚本自己刷。想手动刷自己的那间，
  页面下方「我的宿舍」里还有「立即刷新」。
- 同一间宿舍可能因为换浏览器重扫而留下多条记录。展示时历史会合并，所以看不出来，
  但存储里确实是多份；不清理也不影响使用。
- 学校返回的是估算值，页面原话是「请以实际电表为准」。
