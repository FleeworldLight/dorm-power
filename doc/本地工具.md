# 本地工具（`monitor.py`）

跑在自己电脑上的单人版：查一次余额、写历史、生成看板 HTML，
并顺手把结果上报给在线看板。全程零第三方依赖，只用 Python 标准库 + 你本机已装的 Microsoft Edge。

## 为什么这么绕

该站没有账号密码登录，入口 `/electricity_system/index/pay` 强制 302 到支付宝 OAuth
（`app_id=2018082461109526`，`scope=auth_user,auth_base,auth_ecard`）。
真正的数据接口 `POST /electricity_system/index/getReserveAM` 认的是
「支付宝绑定过的 PHP 会话」，房间号由服务端在登录后注入页面。

**为什么不能只用 `headless --dump-dom`：**
支付宝的登录会话是**会话级 cookie**，浏览器进程一退出就丢。
实测即使加上 `session.restore_on_startup` + `--restore-last-session`，
无头模式要么丢 cookie、要么直接挂住，每次重开浏览器都会退回扫码页。

## 本工具的做法

1. **`login`** —— 开一个带调试端口的 Edge，你扫码登录后，
   用 CDP 把浏览器里的 cookie 全量导出成明文存到 `data/cookies.json`。
2. **`check`** —— 先用存下来的 `PHPSESSID` 直接 HTTP 请求（最快最稳）；
   若 PHP 会话过期，则开一个无头 Edge，用 CDP 把存下来的 cookie
   **重新注入**（关键一步，绕过了会话 cookie 不落盘的问题），
   再打开页面取余额，并顺手把刷新后的 cookie 存回去。
3. 只有支付宝侧的登录态也彻底过期时，才需要重新跑一次 `login`。

注意：**重新注入 cookie 那一步只有本地版能做**。线上服务为了省资源，
在扫码结束后就关掉浏览器，后续刷新只靠 HTTP 重放 —— 所以线上需要
`/index/pay` 探针确认会话还活着。

## 用法

```bash
python monitor.py login      # 首次登录（弹出 Edge，手机支付宝扫码）
python monitor.py check      # 查询一次，写历史，刷看板
python monitor.py report     # 只按历史重画看板
python monitor.py status     # 查看配置、cookie 与历史概览
python monitor.py selftest   # 离线自检 CDP 通道（不联网）
python monitor.py serve      # 本地网页版：127.0.0.1:8788 上的按钮式界面
```

`check` 支持 `--log PATH` 追加一行运行记录，方便挂定时任务时留痕。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 查到数据 |
| 2 | 登录态失效，需要重新执行 `login` |
| 3 | 其他异常 |
| 4 | 查到数据但余额低于阈值 |

## 定时任务

Windows 上用计划任务跑每日查询：

```
程序： <python.exe 绝对路径>
参数： "G:\...\订阅电费\monitor.py" check --log data\run.log
起始于：G:\...\订阅电费
```

任务名 `宿舍电费每日查询`，每天 18:00。查 / 改 / 停用：

```powershell
Get-ScheduledTask -TaskName '宿舍电费每日查询'
Disable-ScheduledTask -TaskName '宿舍电费每日查询'
```

（本机 `schtasks.exe` 被安全策略拦掉了，只能用 PowerShell 的 cmdlet。）

## 文件

| 路径 | 内容 |
|---|---|
| `config.json` | 站点、单价、阈值、看板地址、`client_id` |
| `data/cookies.json` | 浏览器导出的 cookie（明文，仅本机） |
| `data/history.csv` | 每次查询的余额历史 |
| `data/room.json` | 当前绑定的宿舍 |
| `data/last_state.json` | 上次查询结果，供 `report` 重画看板 |
| `dashboard.html` | 生成出来的看板 |

## 与线上看板的关系

`config.json` 里的 `report_url` 指向线上服务时，每次 `check` 会把结果
`POST /api/report` 过去；`client_id` 让服务端把同一个人的多次上报归到一条记录，
换宿舍时直接替换而不是新增。

本地版和线上版可以同时用，也可以只用其中一个。
